# NEDOコンテスト2 Phase 1: 荷物39と小棚の搬入衝突

## 結論

停止の直接原因は、15 mmちょうどのX方向隙間をfloat32へ丸めた結果、1.19209285 nm不足したことです。
ただしfloat64に変えるだけでも経路途中で境界判定に失敗するため、正の幾何学的余裕を確保しました。
v15は小棚から約1 µm離す実行座標補正だけを追加し、課題000を9/41個から30/41個、fill_scoreを11.13495563736843から36.161933587822816へ改善しました。
改善実験は最大5回のうち2回で終了し、両回とも同じ結果です。課題001への評価上の悪影響は確認されません。
公式安全マージン・評価関数・v14・既存resultsは変更していません。

## 荷物39と実際の小棚

- 元寸法: (0.65, 0.45, 0.25) m、質量13 kg、剛体（is_soft=false）。
- 姿勢3: Z軸90度回転。世界軸に沿う寸法は(0.45, 0.65, 0.25) m、半寸法は(0.225, 0.325, 0.125) m。
- 幾何学的計画位置: (-0.280, 0.345, 0.666) m。支持荷物20、plan_rank=14。
- 実行時指定位置: (-0.280, 0.345, 0.687) m。既存plannerが棚搬入用の21 mm liftを付加。
- float32で送信された座標: (-0.2800000011920929, 0.3449999988079071, 0.6869999766349792)。
- 実validatorはXを[-0.285, 0.725]へclipし、開始Y=-0.725、搬入高さZ≈0.76699996を使います。
  この荷物のXはclipされません。Y方向へ先に移動し、次にX方向へ移動します。
- 搬入開始時の荷物AABB: X=[-0.505000001192093, -0.05500000119209281]、Y=[-1.05, -0.40]、Z≈[0.64199996, 0.89199996]。
- 小棚は本体の壁メッシュではなく、独立したGEOM_BOX（この場面のbody ID=3）。
  作成時の寸法(0.44, 0.04, 1.37)をX軸90度回転し、世界軸では(0.44, 1.37, 0.04)となります。
  中心(-0.74, 0, 0.825)、AABB X=[-0.96,-0.52]、Y=[-0.685,0.685]、Z=[0.805,0.845]。

荷物と小棚は開始時からY/Z投影が重なります。衝突形状自体に貫通はなく、X方向の隙間が15 mm境界にあります。
数学的な隙間は -0.28 - 0.225 - (-0.52) = 0.015 m。
float32化後は0.014999998807907153 mとなり、公式getClosestPoints(distance=0.015)が接近点を返すためY区間のstep 0で停止します。
したがって1.2 nm不足は直接の停止理由ですが、Y/Zの投影重なりとX方向が境界ちょうどという幾何学的条件が前提です。
物理時間を進める前の経路検査であり、荷物の変形やsettlingがこの停止を起こしたわけではありません。

## C++とPyBulletの違い

v14が呼ぶcheck_transport_like_safe_gridは既配置荷物のみを対象とし、小棚を渡していません。
またC++ safe-gridの入口はmax(start_margin, safety_margin+0.003)=18 mmを用い、開始X=-0.277。
実validatorのstart_marginは10 mmで、開始X=-0.2800000011920929です。
v14の別の静的棚チェックは棚との幾何学的重なりを見ますが、15 mmの近接マージンを加えていません。
このためv14ではC++=OK、静的棚チェック=OK、path_ok=Trueであっても公式PyBulletは拒否します。

C++ v05の小棚を含むcheck_transport_path_with_shelvesへ**実validatorの経路と15 mm**を渡す追加テストでは、
旧座標はY step 0でNG、補正座標は全109検査点でOKでした。C++本体の変更は不要です。
候補を選ぶ全モデルの統一は今回は行わず、確認できた境界付近の実行座標の修正を優先しました。

## 仮説検証と最小修正

公式validatorと実際の小棚だけを使用した切り分けテスト:

|入力|公式の搬入判定|
|---|---|
|元のfloat32|開始点でNG、距離0.014999998807907153 m|
|元のfloat64|Y=-0.475 mでNG、距離0.014999999999999998 m|
|Xを+1 nm、float64|OK|
|Xを+1 nmまたは+10 nm、float32|元座標へ丸められてNG|
|Xを+0.1 µm、float32|OK|
|Xを+1 µm、float32|OK|
|Xを-1 µm|NG（安全距離不足）|

v15はv14を継承し、_clamp_to_safe_marginの共通経路に境界処理を追加しました。
小棚の右側で、隙間が公式マージン±1 µmの範囲にあり、Y/Zの搬入投影が接近する場合だけ、
小棚右端+荷物半幅+15 mm+1 µmへXを補正します。
float32化で余裕を失う場合はnp.nextafterで外側に丸め、コンテナ内包条件も維持します。
荷物番号による特別扱い、候補スコア・探索順序の変更、公式判定の許容誤差の追加はありません。
大きく不足する経路は補正対象外です。棚から離れた位置や床近傍の安全な位置も変更しません。

荷物39の補正後X=-0.2799989879131317 m、実効移動量≈1.013 µm。
PyBulletによる経路最小隙間は0.015001012086868245 m。15 mmを厳密に超えます。
実行座標の計画時検査と実際の送信が同じクランプを通るため、出力後だけの未検査補正は行いません。
改善前後のBPP計画JSONは完全一致しました。

## 残る課題

30/41個からの続きは、未計画荷物38/31/2や他の未採用荷物に対する候補・順序探索の別問題です。
固定棚の全ての位置関係、主棚、他の姿勢、非公開課題に対する判定モデルの完全一致は保証しません。
静的棚判定の15 mm近接条件、C++ safe-grid入口と実validator入口、天井clip条件の差は次段階で検証すべきです。
今回の小修正は右側の小棚境界付近のみを対象とし、一般のBlocked経路を解決したという主張はしません。
時間予算で探索を打ち切るため負荷条件によって選ぶ計画が変わる可能性は残ります。
mainへのマージは行いません。
